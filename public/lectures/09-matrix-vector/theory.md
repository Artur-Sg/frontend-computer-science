# Теория

## Лекция 09 — Структуры данных на основе массивов: вектор и матрица

## Что разбираем

- Почему массив — фундамент для более сложных структур.
- Как поверх линейной памяти вводятся многомерные контракты доступа.
- Матрица как `view` над плоским буфером.
- Кортежи/структуры поверх `ArrayBuffer` через `DataView`.
- Вектор как динамический массив (`length`, `capacity`, рост буфера).

## 1) Массив как базовая модель

Массив — это линейная последовательность элементов фиксированного размера, расположенных подряд в памяти.

Ключевое свойство:

- доступ по индексу — `O(1)`.

Именно поэтому массив используется как низкоуровневый фундамент для матриц, векторов, хеш-таблиц и других структур.

## 2) От линейного индекса к многомерным координатам

Физически данные остаются в одном линейном буфере, но логически мы можем обращаться к ним по координатам:

- `matrix[row][col]` в 2D;
- `tensor[row][col][depth]` в 3D.

Это достигается формулой отображения координат в линейный индекс.

## 3) Контракт двумерной матрицы

Пусть есть `rows` строк и `cols` столбцов, тогда ёмкость буфера:

- `rows * cols`.

### Row-major (по строкам)

Индекс вычисляется так:

`index = row * cols + col`

Если данные уложены row-major, выгоднее итерировать по строкам (лучше locality и кэш-попадания).

### Column-major (по столбцам)

`index = col * rows + row`

Если данные уложены column-major, выгоднее обходить по столбцам.

## 4) 3D-матрица и порядок укладки

Для 3D размер буфера:

- `rows * cols * depths`.

Возможны разные порядки:

- RowMajor,
- ColumnMajor,
- DepthMajor.

Идея та же: выбираем формулу индекса под сценарий наиболее частого обхода.

## 5) Матрица vs массив массивов

### Матрица на плоском массиве

Плюсы:

- одна аллокация;
- предсказуемая локальность данных;
- меньше накладных расходов GC;
- проще сериализация (один буфер).

Ограничение:

- фиксированная длина строк.

### Массив массивов

Плюсы:

- строки могут быть разной длины.

Минусы:

- много аллокаций (массив + подмассивы);
- хуже locality;
- выше нагрузка на GC;
- сложнее сериализация/десериализация.

## 6) Кортежи и структуры поверх байтов

Вместо «одного числа в ячейке» можно хранить составной элемент фиксированного формата.

Пример кортежа:

- `int32` (4 байта) + `float32` (4 байта) = 8 байт на элемент.

Через `DataView` можно читать/писать поля по смещениям внутри одного `ArrayBuffer`.

Это позволяет:

- хранить гетерогенные поля компактно;
- контролировать формат и endianness;
- сериализовать/передавать данные как единый бинарный блок.

## 7) Вектор (динамический массив)

Вектор обычно описывается тремя параметрами:

- `length` — фактическое число элементов;
- `capacity` — размер выделенного буфера;
- `ptr/buffer` — ссылка на хранилище.

Когда `length === capacity`, буфер увеличивается (часто в 1.5x–2x), данные копируются.

Это даёт:

- дешёвый `push` в среднем (амортизированно `O(1)`),
- но редкие дорогие расширения `O(n)`.

## 8) Практические выводы

1. Матрица — это не «другая память», а другой контракт доступа к тому же линейному буферу.
2. Порядок укладки и порядок обхода должны совпадать.
3. Для плотных вычислений выгоднее плоские/типизированные структуры.
4. Для составных записей (кортежи/структуры) `ArrayBuffer + DataView` даёт компактность и контроль формата.
5. Вектор выигрывает за счёт амортизированного роста capacity.
