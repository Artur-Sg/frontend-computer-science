Реализован `Dequeue<T>` на основе двусвязного списка блоков фиксированного размера:

- каждый узел хранит `items`, `start`, `end`, `prev`, `next`;
- занятый диапазон внутри блока задаётся как `[start, end)`;
- при переполнении края добавляется новый блок слева или справа;
- при опустошении блока после `shift/pop` блок удаляется из списка.

Поддержаны разные типы блоков:

- `Array<T>`;
- числовые `TypedArray`, например `Uint8Array`.

Для сравнения реализован `ReallocDequeue<T>`:

- один непрерывный внутренний массив;
- `start` / `end` / `length` внутри него;
- при нехватке места вызывается `resize` с копированием текущего окна элементов в середину нового массива.

## Что проверено тестами

Покрыты ключевые сценарии:

- пустой дек: `pop` / `shift` возвращают `undefined`;
- `unshift` / `shift`;
- `push` / `pop`;
- FIFO через `push + shift` и `unshift + pop`;
- смешанные операции;
- пример из задания с `Uint8Array`;
- поддержка `Array` и `TypedArray`;
- выход за пределы одного блока;
- `blockCapacity = 1`;
- большой поток операций.

## Бенчмарк

Сравнение: `Dequeue on linked blocks vs ReallocDequeue`.

Параметры:

- `Warmup: 2`
- `Runs: 5`

Сценарии:

- `push/pop` — `200 000` добавлений и удалений с правого конца;
- `unshift/shift` — `200 000` добавлений и удалений с левого конца;
- `mixed` — `push + unshift + pop + shift`;
- `stress growth` — многократные циклы роста и очистки.

## Результаты

| Сценарий | Dequeue на блоках (ms) | ReallocDequeue (ms) | Realloc / Blocks |
|---|---:|---:|---:|
| push/pop | 1.36 | 2.61 | 1.92x |
| unshift/shift | 0.97 | 1.58 | 1.62x |
| mixed | 0.72 | 1.56 | 2.16x |
| stress growth | 2.54 | 1.97 | 0.77x |

## Выводы

В сценариях `push/pop`, `unshift/shift` и `mixed` блочная реализация быстрее. Причина в том, что при росте `Dequeue` не копирует весь массив, а добавляет новый блок.

В сценарии `stress growth` выигрывает `ReallocDequeue`: значение `0.77x` означает, что реализация на одном массиве оказалась быстрее блочной. Это связано с тем, что после расширения `ReallocDequeue` переиспользует уже выделенную память, а блочная версия создаёт и удаляет больше отдельных узлов и блоков.

Практический итог соответствует идее лекции: универсально лучшей структуры данных нет. Выбор зависит от характера нагрузки.
