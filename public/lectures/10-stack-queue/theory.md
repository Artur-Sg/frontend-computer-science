# Теория

## Лекция 10 — Абстрактные структуры данных: стек, очередь, дек

## Ключевая идея

Абстрактная структура данных (АСД) задаёт **контракт**:

- какие операции доступны;
- какие инварианты должны выполняться.

Но АСД не фиксирует конкретную реализацию в памяти.

## Почему это важно

- можно менять реализацию без изменения клиентского кода;
- можно оптимизировать под конкретный сценарий;
- проще рефакторить и масштабировать решения.

## Стек (LIFO)

Стек: `Last In — First Out`.

Базовые операции:

- `push(value)` — добавить элемент;
- `pop()` — удалить/вернуть последний элемент;
- `peek()` — прочитать последний без удаления.

Типичный use-case: call stack, выражения, undo/redo.

## Очередь (FIFO)

Очередь: `First In — First Out`.

Базовые операции:

- `enqueue(value)` / `push(value)` — добавить в конец;
- `dequeue()` / `shift()` — удалить/вернуть первый.

Типичный use-case: обработка задач, события, BFS.

## Двусторонняя очередь (Deque)

Deque (`Double Ended Queue`) разрешает операции с обоих концов:

- `push` / `pop`;
- `unshift` / `shift`.

## Реализация через массив: где проблема

- Стек на массиве работает хорошо.
- Очередь/дек на обычном массиве в JS упираются в `O(n)` для `shift/unshift` (нужно сдвигать элементы).

## Улучшение 1: два указателя и «середина»

Идея:

- хранить данные не с нулевого индекса, а с середины буфера;
- держать `start` и `end`;
- двигать только указатели.

Плюс: `O(1)` для операций на концах.
Минус: при асимметричной нагрузке часть памяти простаивает.

## Улучшение 2: кольцевой буфер

Указатели двигаются по кругу:

- `end = (end + 1) % capacity`
- `start = (start - 1 + capacity) % capacity`

Плюсы:

- `O(1)` на концах;
- полное использование буфера;
- нет сдвигов массива.

## Связный список как альтернатива

Связный список убирает необходимость копирования при расширении:

- узлы добавляются отдельно;
- быстрые вставки/удаления при известном месте.

Цена:

- плохая локальность данных в памяти;
- доступ по индексу `O(n)`;
- часто медленнее массива в обходах из-за cache misses.

## Практический вывод

Идеальной структуры нет:

- массив/вектор: отличная локальность и индексный доступ;
- deque/кольцевой буфер: быстрые операции с концов;
- связный список: гибкость роста, но хуже locality.

Выбор зависит от профиля операций.
