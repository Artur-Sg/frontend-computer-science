# Практика

## Цель

Руками почувствовать разницу между стековой и динамической памятью и подготовиться к реализации собственного менеджера памяти поверх `ArrayBuffer`.

## Шаг 1. Смоделируйте стек

Сделайте простой стек на бинарном буфере:

- выделите `ArrayBuffer`;
- храните указатель вершины;
- реализуйте `push(bytes)` и `pop()`.

Проверьте:

- память выделяется строго по `LIFO`;
- `pop` всегда снимает последний блок;
- при переполнении возникает ошибка.

## Шаг 2. Смоделируйте кучу

Сделайте отдельную модель кучи:

- выделение блока по размеру;
- освобождение по указателю;
- запрет двойного `free`.

Для первого шага подойдёт даже наивная стратегия:

- выдавать блоки подряд;
- хранить таблицу занятых диапазонов;
- при освобождении помечать блок как свободный.

## Шаг 3. Объедините оба региона

Используйте один общий `ArrayBuffer`:

- стек растёт с начала буфера;
- куча растёт с конца;
- между ними должен оставаться свободный промежуток.

Проверьте условие пересечения:

- если стек и куча встретились, память закончилась.

## Шаг 4. Добавьте безопасные указатели

Сделайте объект-указатель, который умеет:

- читать данные (`deref()`);
- изменять данные (`change(...)`);
- освобождать память в куче (`free()`).

Проверьте два инварианта:

- нельзя читать уже освобождённый блок;
- нельзя вызывать `free()` дважды.

## Шаг 5. Продумайте метаданные

Решите, где хранить:

- размер блока;
- тип региона (`stack` / `heap`);
- статус блока (`alive` / `freed`);
- идентификатор, если нужен контроль stale pointers.

Это поможет сделать указатели безопаснее.

## Что важно заметить

- стек прост, потому что всегда освобождает память с вершины;
- куча сложнее, потому что порядок освобождения произвольный;
- безопасность указателей требует дополнительных метаданных;
- общий буфер удобно использовать как учебную модель линейной памяти `Wasm`.
