Реализован класс `HashMap`, который хранит пары `key → value` во внутреннем массиве бакетов.

Внутри таблица устроена так:

- `buckets` — массив бакетов;
- каждый бакет — голова связного списка `EntryNode | null`;
- `size` — текущее число элементов;
- `capacity` — число бакетов;
- `loadFactor` — порог заполненности, после которого таблица расширяется.

### Ключи и хэширование

В реализации отдельно обрабатываются несколько типов ключей:

- строки;
- числа;
- объекты.

Для строк используется `FNV-1a`, для чисел — их целочисленное значение, а для объектов создаётся внутренний числовой id
через `WeakMap`.

Это позволяет стабильно хэшировать один и тот же объект без изменения самого объекта. Если тот же объект используется
повторно, он получает тот же id. Разные объекты, даже с одинаковым содержимым, считаются разными ключами.

### Разрешение коллизий

Коллизии решаются методом цепочек через связный список.

Если несколько ключей попадают в один и тот же индекс, они связываются в цепочку:

```txt
buckets[index] -> EntryNode -> EntryNode -> null
```

Каждый `EntryNode` хранит запись `entry` и ссылку `next` на следующий узел.

При `get`, `has`, `set` и `delete` таблица сначала вычисляет индекс бакета, а затем проходит по связному списку внутри
этого бакета и сравнивает ключи.

### Операции

- `set(key, value)` — вставляет новую пару или обновляет существующую;
- `get(key)` — возвращает значение или `undefined`;
- `has(key)` — проверяет наличие ключа;
- `delete(key)` — удаляет запись и возвращает её значение;
- `clear()` — очищает таблицу.

Если ключ уже существует, `set` не создаёт новую запись, а обновляет старую. В этом случае `size` не увеличивается.

### Расширение буфера

После каждой новой вставки таблица проверяет текущий коэффициент заполнения:

```txt
size / capacity
```

Если он превышает заданный `loadFactor`, число бакетов удваивается. После этого все существующие записи заново
раскладываются по новым индексам уже относительно новой ёмкости.

Это и есть `rehash`: операция дорогая, но происходит редко, поэтому в среднем вставка остаётся быстрой.
