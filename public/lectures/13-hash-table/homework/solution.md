Реализованы две части:

- `HashMap<K, V>` — сама хэш-таблица;
- `DefaultHashStrategy` — стратегия хэширования и сравнения ключей.

Такое разделение убирает логику хэширования из класса таблицы: `HashMap` отвечает только за бакеты, коллизии и
расширение, а `HashStrategy` — за `hash(key)` и `equals(a, b)`.

Конструктор `HashMap` оставлен совместимым с формулировкой задания:

```ts
new HashMap()
new HashMap(120)
new HashMap(120, 0.65, customStrategy)
```

Внутри `HashMap` хранит:

- `buckets` — массив бакетов;
- каждый бакет — голова связного списка `EntryNode | null`;
- `size` — текущее число элементов;
- `capacity` — число бакетов;
- `loadFactor` — порог заполненности, после которого таблица расширяется.

Коллизии решаются методом цепочек через связный список:

```txt
buckets[index] -> EntryNode -> EntryNode -> null
```

Каждый `EntryNode` хранит запись `entry` и ссылку `next`. При `get`, `has`, `set` и `delete` таблица сначала вычисляет
индекс бакета, а затем проходит по списку внутри этого бакета.

### HashStrategy и ключи

`DefaultHashStrategy` отдельно обрабатывает разные типы ключей:

- числа;
- строки;
- boolean;
- symbol;
- bigint;
- `null`;
- `undefined`;
- объекты и функции.

Для примитивов хэш строится из типизированного строкового представления, например:

- `number:42`
- `string:foo`
- `boolean:true`

Дальше эта строка хэшируется через `FNV-1a`.

### Object identity без WeakMap

Если у объекта есть метод `hashCode()`, стратегия сначала вызывает его и строит хэш уже от возвращённого значения.
Это влияет на вычисление хэша и выбор бакета, но равенство ключей по умолчанию всё равно проверяется через `===`.
Это позволяет объекту самому определить, как он хочет участвовать в хэшировании.

Для объектов и функций используется identity-хэш через скрытый `Symbol`:

- если `hashCode()` нет, при первом обращении объект получает внутренний id;
- id записывается в объект через `Object.defineProperty`;
- при повторном использовании того же объекта возвращается тот же id;
- сам id берётся из `objectHashFactory`, поэтому способ генерации можно подменить.

Сравнение ключей выполняется через `===`, поэтому:

- один и тот же объект считается тем же ключом;
- два разных объекта с одинаковым содержимым считаются разными ключами.

Это поведение ближе к обычному `Map`, чем вариант с `JSON.stringify`.

Генерация object hash тоже настраивается: в `DefaultHashStrategy` можно передать собственный `objectHashFactory`. По
умолчанию для object identity используется случайное число.

Если объект нерасширяемый (`Object.freeze`, `Object.seal`, `Object.preventExtensions`), стратегия выбрасывает
ошибку: в такой объект нельзя безопасно записать скрытый `Symbol`-id.

### Операции

- `set(key, value)` — вставляет новую пару или обновляет существующую;
- `get(key)` — возвращает значение или `undefined`;
- `has(key)` — проверяет наличие ключа;
- `delete(key)` — удаляет запись и возвращает её значение;
- `clear()` — очищает таблицу.

Если ключ уже существует, `set` не создаёт новую запись, а обновляет старую. В этом случае `size` не увеличивается.

### Расширение буфера

После каждой новой вставки таблица считает:

```txt
size / capacity
```

Если коэффициент заполнения превышает `loadFactor`, число бакетов удваивается. После этого все существующие записи
перераспределяются по новым бакетам.

Это и есть `rehash`: операция дорогая, но происходит редко, поэтому в среднем вставка остаётся быстрой.
