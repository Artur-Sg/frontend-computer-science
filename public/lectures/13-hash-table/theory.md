# Теория

## Ассоциативный массив

Ассоциативный массив хранит пары `ключ -> значение` и поддерживает базовые операции:

- `set(key, value)`
- `get(key)`
- `has(key)`
- `delete(key)`

В отличие от обычного массива, доступ идёт не по числовому индексу, а по ключу. Ключ должен быть сравнимым, а для
быстрой реализации обычно ещё и хэшируемым.

## Хеш-таблица

Самая популярная реализация ассоциативного массива — хеш-таблица.

Идея простая:

1. вычислить `hash(key)`;
2. превратить хеш в индекс массива бакетов;
3. положить пару в найденный бакет;
4. при поиске повторить те же шаги.

Обычно индекс считают как `hash % buckets.length`.

## Требования к хеш-функции

Хорошая хеш-функция должна быть:

- детерминированной;
- быстрой;
- достаточно равномерной;
- устойчивой к банальным наборам похожих ключей.

Для учебной реализации часто хватает простой функции для строк, но важно понимать, что плохой хеш быстро приводит к
скоплению элементов в одних и тех же бакетах.

## Коллизии

Коллизия — это ситуация, когда разные ключи попадают в один и тот же бакет.

Коллизии неизбежны:

- множество возможных ключей очень велико;
- число бакетов ограничено.

Поэтому хеш-таблица всегда должна иметь стратегию разрешения коллизий.

## Метод цепочек

Самый понятный и распространённый способ — chaining, или метод цепочек.

Тогда каждый бакет хранит не одно значение, а список записей:

```txt
buckets[5] = [
  { key: "foo", value: 1 },
  { key: "oof", value: 2 },
]
```

Если два ключа попали в один бакет, поиск продолжается уже внутри этого списка.

Плюсы:

- простая реализация;
- удаление удобно делать локально внутри бакета;
- можно спокойно хранить больше элементов, чем бакетов.

Минусы:

- дополнительный overhead на массивы/списки бакетов;
- при плохом распределении цепочки растут и деградируют к `O(n)`.

## Load factor и rehash

Ключевая метрика хеш-таблицы — коэффициент заполнения:

```txt
loadFactor = size / buckets.length
```

Когда он становится слишком большим, бакеты растут, цепочки удлиняются и производительность падает.

Обычное решение — `rehash`:

1. создать новый массив бакетов большего размера;
2. заново вставить туда все элементы;
3. пересчитать индексы уже относительно нового размера.

Это дорогая операция `O(n)`, но она происходит редко, поэтому в среднем вставка остаётся близкой к `O(1)`.

## Сложности

| Операция | Средний случай | Худший случай |
| --- | --- | --- |
| `get` | `O(1)` | `O(n)` |
| `set` | `O(1)` | `O(n)` |
| `delete` | `O(1)` | `O(n)` |

Худший случай возникает, если все ключи склеились в один бакет.

## Object, Map и WeakMap в JavaScript

В JavaScript ассоциативное поведение встречается в нескольких формах:

- `Object`
- `Map`
- `WeakMap`

### `Object`

`Object` подходит для небольших и относительно статичных наборов строковых ключей. Но у него есть ограничения:

- ключи приводятся к строке или `symbol`;
- есть прототип и унаследованные свойства;
- порядок обхода имеет специфику;
- `delete` может переводить объект в менее оптимальный режим.

### `Map`

`Map` лучше подходит для динамических словарей:

- поддерживает любые типы ключей;
- не конфликтует с прототипом;
- сохраняет порядок вставки;
- даёт предсказуемый API: `set/get/has/delete`.

На практике для прикладного кода `Map` обычно удобнее самодельной хеш-таблицы, но учебная реализация полезна, чтобы
понять, откуда берутся коллизии, rehash и амортизированная сложность.

### `WeakMap`

`WeakMap` хранит ключи по слабой ссылке:

- ключами могут быть только объекты;
- если объект-ключ больше нигде не используется, запись исчезает вместе с ним;
- структуру нельзя нормально перечислять.

Это инструмент для кэшей и приватных данных, а не универсальный словарь.

## Когда что использовать

- Если нужна учебная структура и контроль над алгоритмом — своя хеш-таблица.
- Если нужен рабочий динамический словарь в JS — обычно `Map`.
- Если данные жёстко фиксированы по схеме — объект или структура.
- Если кэш должен не мешать GC — `WeakMap`.
